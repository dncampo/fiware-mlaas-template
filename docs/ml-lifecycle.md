# ML lifecycle: separated stages

## A. Offline training and evaluation

- Download a documented, accessible Water Potability dataset; record source, license, checksum and target name.
- Reserve 10% **before** training/model selection for demo replay. Split the remaining data into train, validation and test, aiming for 60/15/15/10 of all rows.
- Use stratification with a fixed seed; preprocessing fit only on training split; pipeline includes missing-value imputation.
- Train one conventional classifier (Random Forest first); record accuracy, balanced accuracy, precision, recall, F1 and confusion matrix. Report class balance and limitations.
- Save exact preprocessing+estimator artifact, feature order, output semantics and version. Optionally log runs to local MLflow Tracking.
- **Not automated:** sensor updates do not retrain anything.

## B. Explicit deployment and registration

- Use an explicit local command/script to serve the model at a known HTTP endpoint (MLflow Models serving is preferred); test prediction independently before registration.
- Publish `MLModel` as discoverable NGSI-LD metadata for the **specific** ready version.
- Publish one `MLProcessing` with `refMLModel`, source selection (`entities`, watched attributes, optional `q`), input mapping and output type.
- Adapter creates/reconciles a real broker subscription with its callback endpoint. Registering/deploying a model is not automatic just because an entity was created.

## C. Runtime

- Injector posts a fresh immutable `WaterQualityObserved` from the reserved replay partition.
- Broker evaluates subscription and sends HTTP notification only when its supported conditions match.
- Adapter resolves source ID, collects complete attributes, applies mapping and calls serving endpoint.
- Adapter creates one `MLPrediction` with Relationships to the original observation, pinned model version and processing.
- Web UI shows actual activity, source and prediction. This is the only automatic phase in the initial PoC.

## Versioning

A new trained artifact => new version and new `MLModel` entity. Deployment and `MLProcessing` binding are explicit, not automatic; do not silently swap the model under an existing processing. An MLflow Model Registry is **not mandatory** for this local template. Store model artifacts locally and optionally use MLflow tracking; explain paths for Docker volumes vs. host filesystem.

## Limitations

This dataset is a teaching example and cannot establish real potable-water safety. It is a static tabular dataset, **not real-time sensor telemetry**. Replay timestamps are generated by the demonstrator and must not be misrepresented as original sensor observation times.

## Implemented commands and provenance

`python -m mlaas.train --version v1` performs the offline preparation and training
step explicitly. The source is Aditya Kadiwal's
[Water Potability dataset](https://www.kaggle.com/datasets/adityakadiwal/water-potability),
listed as CC0 Public Domain by the upstream Kaggle API on 2026-11-03. The script
uses a public CSV mirror and verifies SHA256
`904004bde729bfe3d2e195f46343bceead09e32a0eb95bb8184e7e20e029b2bf`.
A changed mirror is rejected. Raw CSV and its original numeric precision remain
on disk; metadata records both origin and download URLs. No dataset is committed.

All splits use stratification and seed 42. The resulting row counts are 1965
train, 491 validation, 492 test and 328 demo. Saved original row indexes make the
splits reproducible and auditable. There is one estimator and no hyperparameter
search; validation and test are evaluated after fitting. The imputer medians are
checked against training rows, never the entire dataset. The saved pipeline
contains preprocessing and classifier together.

The version directory includes `model/` (MLflow sklearn and pyfunc flavors),
`metadata.json`, `metrics.json`, `splits.json`, and label-free `demo.csv`.
MLflow records parameters, metrics and all artifacts in local `mlruns/` using its
file tracking backend. No Model Registry is used. The training command refuses
to overwrite a version, including a partially created version after failure;
inspect that directory and choose a new version or remove only the failed output
before retrying. Do not remove or modify an already deployed version.

`docker compose up -d --build --wait` explicitly starts the pinned serving
process. `python -m mlaas.cli register-model` independently invokes its HTTP
endpoint using a real demo row, then creates metadata. The separate
`register-processing` command posts the processing and calls subscription
reconciliation. Registration is create-only. If processing creation succeeded
but reconciliation failed, fix the dependency and call `/processings/reconcile`
again; do not overwrite the processing.

On the measured test partition, the majority-class accuracy baseline is 300/492
(0.610). Random Forest accuracy is 0.644, balanced accuracy 0.571, precision 0.613,
recall 0.240 and F1 0.345. Confusion matrix (actual rows, predicted columns,
labels 0 and 1) is `[[271,29],[146,46]]`. Low class-1 recall is a substantial model
limitation, not a deployment failure. No confidence score is emitted because
the selected sklearn serving contract returns class labels only.

## Explicit demo cleanup

Reset Demo is separate from training, serving and registration. After user
confirmation it deletes only ownership-journaled replay sources and their
adapter-generated predictions, verifies their absence, then removes the
associated dedup jobs and trace. No artifacts, metrics, registered configuration
or subscriptions are removed. Counters and replay position reset only after all
source groups succeed. Replaying a deleted sample uses its original stable ID;
it never overwrites an existing observation. A failed or interrupted reset must
be retried before demo inference or replay resumes. Pre-upgrade and external
sources remain outside this cleanup boundary. See [architecture](architecture.md)
for the per-source commit order and delayed-notification handling.
